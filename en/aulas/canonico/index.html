Lesson 4 · 13 min

One canonical only: www or non-www

To you, yoursite.com and www.yoursite.com are the same site. To a search engine, they can be two. When the canonical, the sitemap, and the links disagree, Google picks on its own which address to keep, and sometimes it picks the wrong one. This lesson closes that door.

Start the lesson

In this lesson you will

  1. 1What a canonical is and why it decides which URL counts
  2. 2Redirect the variations to a single one
  3. 3Check the 4 places where the address appears
  4. 4The real case of the non-www canonical

Goal: choose www or non-www and make canonical, sitemap, JSON-LD, and links use the same address.

01 · From the address you type to the address that counts

Tap each block.

Click each block in the diagram to see what it does.

It doesn't matter whether you use www or not. What matters is making one choice and using it everywhere.

02 · Fix the address

Tap each step.

1. Choose

See which version Search Console already shows most, and which one outside links use. Stick with that one.

Changing later is costly: choose once and write it down.

2. Redirect

The redirect rule lives at your host, on the server, or on the CDN. Ask your provider for a permanent redirect from the version that doesn't count to the one that does.

Check with the X-ray: all three variations should end at the same address with 200.

3. Check the page

In the X-ray, the canonical line for each page should show the address you chose. Empty or different is a finding.

Watch out for parts of the site generated by another system (blog, knowledge base, store): that's where the canonical tends to differ.

4. Check the rest

Open the sitemap and see whether the URLs use the same version. Do the same in the JSON-LD and in the menu and footer links.

If part of the HTML is generated by a script, fix it in the generator, or the fix disappears on the next build.

At INEMA (10/02/2026)The canonical for /conhecimento/ was missing www, while the portal's sitemap used www. The fix went into the repository and the generator, with a note so no one undoes it.

03 · Check from the terminal

The same commands the X-ray uses, one at a time.

Terminal · where each variation goes
for u in http://www.seusite.com/ https://seusite.com/ https://www.seusite.com/; do
  echo "$u -> $(curl -4 -m 20 -s -o /dev/null -w '%{http_code} %{redirect_url}' "$u")"
done
Terminal · the canonical of a page
curl -4 -m 20 -s https://www.seusite.com/pagina/ | grep -oE 'rel="canonical" href="[^"]*"'
Table of the 4 places (template)
Versão escolhida: <https://www.seusite.com>
| lugar | página conferida | endereço encontrado | igual? |
|---|---|---|---|
| canonical | </pagina/> | <...> | sim/não |
| sitemap | <sitemap.xml> | <...> | sim/não |
| JSON-LD (@id/url) | <home> | <...> | sim/não |
| links do menu | <home> | <...> | sim/não |
Example from the repository

Redirects for www.inema.club in the 10/19/2026 X-ray:

http://www.inema.club/ -> 308 https://www.inema.club/
https://inema.club/ -> 308 https://www.inema.club/
https://www.inema.club/ -> 200

Both variations redirect permanently to the www version, which answers 200.

  • A temporary redirect (302) instead of a permanent one.
  • Canonical pointing to the home page on every page: the search engine understands that only the home page counts.
  • Fixing the generated HTML instead of the generator: the error comes back on the next build.
