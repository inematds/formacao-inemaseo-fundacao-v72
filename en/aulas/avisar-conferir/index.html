Lesson 8 · 18 min

Notify the search engines and check indexing

With the foundation ready, every publication closes with two steps: notify the search engines that the URL exists and, a few days later, check whether it made it into the index. Notifying a broken URL burns trust; not checking leaves an important page forgotten. At the end, you build the dated plan for the whole course.

Start the lesson

In this lesson you will

  1. 1Publish the IndexNow key
  2. 2Notify only with URLs that return 200
  3. 3Read the URL Inspection statuses
  4. 4Build the dated foundation plan

Goal: notify IndexNow and Bing only with URLs that return 200, and check indexing in URL Inspection.

02 · Notify and check without stumbling

Tap each step.

1. The key

Create a key of 32 or more hexadecimal characters (numbers and letters from a to f) and publish it at https://seusite.com/[sua-chave].txt, with only the key inside.

It isn't a secret: it's public by design, and it proves the site is yours.

At INEMA (10/02/2026)The news site's first submission came back 403 SiteVerificationNotCompleted: the key had just been published. Resubmitting after about 4 minutes fixed it.

2. The list

One URL per line, all from the same domain, only what's new or changed.

Don't resubmit the whole site every time something changes.

3. The submission

Run the script with the key in the INDEXNOW_KEY variable. With BING_API_KEY, it also uses the Bing Webmaster API (optional).

The expected response is HTTP 200 or 202.

At INEMA09/24/2026: 109 URLs through IndexNow, response 202. 10/02: 90 URLs through Bing and IndexNow, response 200.

4. The check

A week later, inspect the key URLs in Search Console. Write down the status of each one.

The gsc_inspecionar.py script does the same in batch, but it needs a Google credential; start with the dashboard.

At INEMAOn 10/05/2026, 12 of 14 key URLs were indexed; on 10/13, 13 of 14. Only /eventos/ was missing, "unknown to Google".

03 · The files and the commands

Replace what's between < > with your own. The Bing key is optional.

urls.txt (one per line)

Terminal · notify (IndexNow, and Bing if you have a key)
INDEXNOW_KEY=<sua-chave> bash tools/avisar_buscadores.sh urls.txt

# optional, with the Bing Webmaster API key:
INDEXNOW_KEY=<sua-chave> BING_API_KEY=<chave-bing> BING_SITE=https://www.seusite.com/ bash tools/avisar_buscadores.sh urls.txt
Terminal · batch inspection (template; needs a Google credential)
# requires authenticated gcloud and GSC_QUOTA_PROJ set
python3 tools/gsc_inspecionar.py sc-domain:seusite.com https://www.seusite.com/pagina/

Simulation: illustrative example
IndexNow: HTTP 202

If a URL doesn't respond with 200, the script stops before sending:

NÃO 200 (404): https://www.seusite.com/pagina-errada/
corrija as URLs acima antes de avisar
https://www.seusite.com/pagina/
   Enviada e indexada | rastreio 2026-10-13 | canônico Google https://www.seusite.com/pagina/

Status, the date of the last crawl, and the canonical that Google chose.

  • Notifying before the deploy finishes: the URL still returns a 404.
  • Waiting for IndexNow to reach Google: Google doesn't take part; use the sitemap and URL Inspection.
  • Promising that IndexNow "gets you into ChatGPT": it notifies search engines, but it doesn't guarantee a citation.

04 · Practice: your first notification and your first check

E2 asks for a few days between notifying and inspecting.

E1 · Key and first notification

30 min

Publish your IndexNow key on your site, build the urls.txt file with 3 to 5 URLs, and run avisar_buscadores.sh.

Done when: the script responded IndexNow: HTTP 200 or 202 and no URL was rejected for not responding with 200.

E2 · Five URLs inspected

25 min

A week later, inspect your 5 most important URLs in Search Console and fill in the log.

Done when: the log has 5 rows with status, crawl date, and Google's canonical; the ones that aren't indexed have a next step.
