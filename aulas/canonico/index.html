Aula 4 · 13 min

Um canônico só: www ou sem www

Para você, seusite.com e www.seusite.com são o mesmo site. Para o buscador, podem ser dois. Quando o canônico, o sitemap e os links discordam, o Google escolhe sozinho qual endereço guardar, e às vezes escolhe o errado. Esta aula fecha essa porta.

Começar a aula

Nesta aula você vai

  1. 1O que é canônico e por que ele decide qual URL vale
  2. 2Redirecionar as variações para uma só
  3. 3Conferir os 4 lugares onde o endereço aparece
  4. 4O caso real do canônico sem www

Objetivo: escolher www ou sem www e fazer canonical, sitemap, JSON-LD e links usarem o mesmo endereço.

01 · Do endereço digitado ao endereço que vale

Clique em cada bloco.

Clique em cada bloco do diagrama para ver o que ele faz.

Não importa se é com ou sem www. Importa ser uma escolha só, em todo lugar.

02 · Acertar o endereço

Clique em cada etapa.

1. Escolher

Veja qual versão o Search Console já mostra mais e qual os links externos usam. Fique com ela.

Mudar depois custa caro: escolha uma vez e anote.

2. Redirecionar

A regra de redirecionamento fica na hospedagem, no servidor ou na CDN. Peça ao seu fornecedor um redirecionamento permanente da versão que não vale para a que vale.

Confira com o raio-x: as três variações devem terminar no mesmo endereço com 200.

3. Conferir a página

No raio-x, a linha canonical de cada página deve mostrar o endereço escolhido. Vazio ou diferente é achado.

Cuidado com partes do site geradas por outro sistema (blog, base de conhecimento, loja): é onde o canônico costuma divergir.

4. Conferir o resto

Abra o sitemap e veja se as URLs usam a mesma versão. Faça o mesmo no JSON-LD e nos links do menu e do rodapé.

Se uma parte do HTML é gerada por script, corrija no gerador, senão a correção some no próximo build.

No INEMA (02/10/2026)O canônico do /conhecimento/ estava sem www, enquanto o sitemap do portal usava www. A correção foi no repositório e no gerador, com aviso para não desfazer.

03 · Conferir pelo terminal

Os mesmos comandos que o raio-x usa, um de cada vez.

Terminal · para onde vai cada variação
for u in http://www.seusite.com/ https://seusite.com/ https://www.seusite.com/; do
  echo "$u -> $(curl -4 -m 20 -s -o /dev/null -w '%{http_code} %{redirect_url}' "$u")"
done
Terminal · o canônico de uma página
curl -4 -m 20 -s https://www.seusite.com/pagina/ | grep -oE 'rel="canonical" href="[^"]*"'
Tabela dos 4 lugares (modelo)
Versão escolhida: <https://www.seusite.com>
| lugar | página conferida | endereço encontrado | igual? |
|---|---|---|---|
| canonical | </pagina/> | <...> | sim/não |
| sitemap | <sitemap.xml> | <...> | sim/não |
| JSON-LD (@id/url) | <home> | <...> | sim/não |
| links do menu | <home> | <...> | sim/não |
Exemplo do repositório

Redirecionamentos de www.inema.club no raio-x de 19/10/2026:

http://www.inema.club/ -> 308 https://www.inema.club/
https://inema.club/ -> 308 https://www.inema.club/
https://www.inema.club/ -> 200

As duas variações redirecionam de forma permanente para a versão com www, que responde 200.

  • Redirecionamento temporário (302) no lugar do permanente.
  • Canônico apontando para a home em todas as páginas: o buscador entende que só a home vale.
  • Corrigir o HTML gerado e não o gerador: o erro volta no próximo build.

04 · Prática: um endereço só

Use o raio-x.txt da aula 2 como ponto de partida.

E1 · As três variações

15 min

Rode o laço de curl (ou o raio-x de novo) e veja para onde vai cada variação do endereço.

Pronto quando: as três variações terminam no mesmo endereço, com 200 no final; se não, o pedido de correção foi feito à hospedagem.

E2 · Os quatro lugares

25 min

Preencha a tabela dos 4 lugares para a home e para uma página interna.

Pronto quando: a tabela está completa e toda linha diz "sim", ou cada "não" tem a correção anotada.
